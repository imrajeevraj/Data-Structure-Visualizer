|---|---|

| Random linear | 1,000 linked-list updates and 600 each stack/queue updates compared with reference collections |
| Validation | 30-node cap on every model, malformed/empty/out-of-range integers, state preserved on errors |
| Snapshot isolation | Saved frames survive subsequent insertion/deletion; immutable list prevents edits |
| Demo correctness | Four rotation presets and sorted-input heights: BST 7, AVL 3 |
| Playback | Next, previous, seek bounds, timer completion, play/pause, replay and cancel |
| UI integration | Input/button actions, mutation lock while rewound, reset, final-frame unlock, render/export layouts |

The acceptance run executed **718,260 assertions** across these 12 groups, including checks repeated for every node in randomized states. That is an assertion count, not 718,260 independent test cases. The JUnit adapter reruns the same underlying cases; its 12 tests are not 12 additional independent suites.

## Visual evidence

Actual Swing components were rendered with a headless harness. Final images were visually inspected for the empty workspace, AVL LR rotation, completed AVL tree, 1280×720 layout and 30-node linked list. Stack/queue workspace renders and a 30-node skewed BST export are generated by the harness as well. Long structures intentionally use scrolling instead of shrinking every node to unreadability.

## Reproduce

```powershell
.\build.ps1 -Test
```

This writes `build/test-results.txt` and screenshots to `build/qa`. Maven users can run `mvn test`. The recorded JUnit run used the official standalone console JAR because Maven was not installed; source for the adapter is included.

Manual export-dialog selection, overwriting an existing PNG, interactive quiz dialogs, screen-reader behavior and another operating system were not automated. No user study or performance benchmark has been performed.
